# Boards Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the always-saved hotkey and holding-tank layout with saved **boards** per profile and a separate crash-recovery record. A clean exit throws the night away, and opening a profile loads its active board as it was saved.

**Architecture:**
- The main process owns two stores, both written atomically:
  - one `boards.json` per profile;
  - one recovery record per profile, kept outside the profile directory.
- A main-process session lifecycle tracks loading, ready and failed states and decides which exits are clean. It also builds the Board menu from the current board document.
- The renderer applies a layout in place. It fetches song rows first, then applies them in one synchronous step, so a board switch never touches the playing sound.
- Profile switching keeps PR 823's in-process switch, followed by a page reload. That reload still stops audio, which is accepted for this project.

**Tech Stack:** Electron (main + contextIsolated preload), vanilla ES-module renderer, node-sqlite3-wasm, Vitest, Playwright.

**Spec:** `docs/superpowers/specs/2026-10-17-boards-design.md`, as amended by the review (`2026-10-17-boards-design-review.md`), PR 823's design note (`2026-10-17-in-process-profile-switch-design.md`, on the branch) and the decisions below. Where they disagree, **this plan's "Amendments" section wins**.

## Amendments to the brief (decided 2026-10-20)

1. **Profile switch is PR 823's in-window dialog.** Cancelling it, or picking the same person, leaves the live session untouched in memory. Nothing is restored, because nothing was torn down. There is no hand-off token for profile switch.
2. **A profile switch still reloads the page and stops audio.** Keeping audio through a profile switch is a separate later project. A **board** switch keeps the song playing.
3. **Song ids are never reused.** The `mrvoice` table is rebuilt once with `AUTOINCREMENT`. Boards store bare ids. Loading drops ids that are missing from the library, in the live session only, and says how many it dropped.
4. **View → Start a New Session becomes Board → Revert to "<board>".** It asks once, then reloads the active saved board.
5. **Rename and Delete work on any board**, from submenus. Deleting a board that isn't active never touches the live session.
6. **Imported copies are named `<board> (<source profile>)`**, with ` 2`, ` 3`… added on a name collision. Each copy records `importedFrom`.
7. **Storage guarantees:**
   - every write is atomic (temp file, fsync, rename);
   - `boards.json` keeps one previous generation, `boards.json.prev`;
   - a file that can't be read is never treated as empty and never overwritten;
   - `state.json` is never written again. It stays frozen so an older build that is run again still opens the pre-upgrade layout.
8. **Exit classification:**

   | Exit | Effect on recovery |
   | --- | --- |
   | Quit, close the window, Windows session-end | clean: retire |
   | Profile switch (to a different profile) | clean for the old profile: retire |
   | Board switch, Revert, deleting the active board | retire |
   | Library import (restart) | clear all recovery |
   | Backup restore | retire the current profile's recovery |
   | Update install | hand-off: restore silently on the next open, if within 15 minutes |
   | Delete Current Profile | that profile's recovery is removed |
   | Renderer crash | crash: never retire. Offer a reload that restores silently |
   | Main-process crash, kill, power loss | crash: prompt on the next open of that profile |

9. **A layout equal to the saved board is never written as recovery**; any existing record is retired instead, so an untouched show never prompts after a crash. Recovery always belongs to the profile that opened the session.
9b. **Update, New Board, Revert and Delete are disabled until the session is `ready`.** A failed load stays `failed`. It never falls through to an empty layout.
10. **Board swap playback contract:**
    - the playing sound and `#song_now_playing` are untouched;
    - `.now_playing`, `#selected_row` and `.active-hotkey` are cleared;
    - switching to Playlist mode afterwards does not reattach to the new holding tank.
11. **Menu keys:**
    - the Hotkeys menu is removed;
    - `Cmd/Ctrl+O` and `Cmd/Ctrl+S` are left unbound;
    - nothing in the Board menu has an accelerator.

## Global Constraints

- No bundler. Renderer imports are relative `.js` paths. npm packages are only available as `window.*` globals.
- Every `secureElectronAPI` call returns `{ success, ... }`. Unwrap the result before using it.
- Renderer modules `export default` and are registered in `src/renderer/modules/app-bootstrap/module-config.js`.
- Every new IPC channel goes in `src/shared/ipc-channels.cjs` and is exposed in `src/preload/modules/secure-api-exposer.cjs`. `tests/unit/main/ipc-drift-guard.test.js` must stay green. Run `npm run build:preload` after preload edits.
- Validate every IPC argument that names a profile or a board:
  - profile names against `profileManager.profileExists()`;
  - board ids against `/^[0-9a-f-]{36}$/`.
- Never `path.join` an unvalidated id.
- The board document has `version: 1`. Readers reject a higher version without overwriting the file.
- Profile and board names are compared trimmed and case-insensitive (`toLocaleLowerCase('en-US')`). Names are at most 50 characters.
- The first board created by migration is named exactly **`Board`**.
- The Board menu never uses the words Open, Save or Save As.
- No `test.skip`, `it.skip`, `describe.skip` or `test.fixme`. Coverage floors in `vitest.config.js` (currently lines 40, functions 39, statements 39, branches 33) are raised at the end of each phase to the new measured floor, rounded down.

- Logging uses `debugLog?.info/warn/error(msg, { module, function, ... })`.
- Modals go through `safeShowModal`/`safeHideModal`. Prompts go through `customConfirm`/`customPrompt` (`src/renderer/modules/utils/modal-utils.js`).

## Review Focus

1. **Corrupt or half-written `boards.json` at open.** Expect: load `boards.json.prev` and show "Mx. Voice couldn't read this profile's boards and opened the previous copy". Never an empty board, and the bad file is kept as `boards.json.corrupt-<ts>`. Test in Task 3.
2. **Board switch during a playing playlist track.** Expect: the song plays to the end, nothing advances, no row or key stays highlighted, and switching the mode to Playlist afterwards doesn't attach. Test in Task 8.
3. **Update clicked while loading, or after a load failed.** Expect: the menu item is disabled, and a direct IPC call is refused with `session not ready`. Test in Tasks 6b and 10.
4. **A saved board references a song deleted from the library.** Expect: that slot loads empty, a notice says "1 song in this board isn't in the library", and a new import never gets that id. Test in Tasks 5 and 8.
5. **Board names with `&`, quotes, 50 characters, or a case-only duplicate.** Expect:
   - the menu shows `&` literally on Windows and Linux;
   - the header shows the full name, CSS-truncated;
   - a case-only duplicate is rejected on New and Rename, and suffixed on Import.

   Test in Tasks 2 and 10.

### Task 1: Atomic JSON file helper

**Files:**
- Create: `src/main/modules/atomic-json-file.js`
- Test: `tests/unit/main/atomic-json-file.test.js`

**Interfaces — Produces:**
- `writeJsonAtomic(filePath: string, value: any, { keepPrevious?: boolean }): Promise<void>`. Writes `<file>.tmp-<pid>-<n>`, fsyncs it, renames it over the target, then fsyncs the directory where that's supported. With `keepPrevious`, it first copies the existing target to `<file>.prev`.
- `readJsonWithFallback(filePath: string): Promise<{ status: 'ok'|'missing'|'recovered'|'unreadable', value?: any, error?: string }>`:
  - `recovered` means the main file failed to parse and `.prev` parsed;
  - `unreadable` means both failed.
- `quarantine(filePath: string): Promise<string>`. Renames the file to `<file>.corrupt-<ISO ts>` and returns the new path.
- On Windows, a rename over an existing file can fail for a moment with `EPERM`, `EBUSY` or `EACCES` while antivirus or the search indexer holds it. Retry the rename up to 5 times with 20 ms, 40 ms, 80 ms… backoff, then throw. Directory fsync isn't supported on Windows, so skip it there.

### Task 5: Never reuse song ids

**Files:**
- Modify: `src/main/modules/database-setup.js`. Add `ensureAutoincrementIds(db, { dbPath, fs })`, called after `migrateDatabase(db)` and before `setupDatabaseIndexes` on both init paths (~lines 184 and 214).
- Test: `tests/unit/main/database-autoincrement.test.js` (real node-sqlite3-wasm on a temp file, like `database-setup-schema.test.js`)

**Interfaces — Produces:** `ensureAutoincrementIds(db, { dbPath, fs }): { rebuilt: boolean }`

Approach:
- If `sqlite_master.sql` for `mrvoice` already contains `AUTOINCREMENT`, return `{rebuilt:false}`.
- Otherwise:
  1. copy the db file to `<dbPath>.pre-autoincrement` (once; don't overwrite an existing copy);
  2. `BEGIN`;
  3. create `mrvoice_new` with `id INTEGER PRIMARY KEY AUTOINCREMENT` and every current column, read from `PRAGMA table_info(mrvoice)`;
  4. `INSERT INTO mrvoice_new SELECT * FROM mrvoice`;
  5. `DROP TABLE mrvoice`, then `ALTER TABLE mrvoice_new RENAME TO mrvoice`;
  6. upsert `sqlite_sequence(name='mrvoice', seq=MAX(id))`;
  7. `COMMIT`.

  Roll back on any error and leave the table untouched.
- No code in `src/main` uses transactions yet. node-sqlite3-wasm provides `db.exec(sql)` for `BEGIN`, `COMMIT` and `ROLLBACK`, and `db.inTransaction` to check state. Use them; don't rely on the prepare/run helpers for these.
- The rebuild runs at startup, before any IPC query is served. Time it on a copy of a large real library (10k+ rows) and record the number in the PR. If it takes over 2s, show the existing startup splash text `Updating your library…` while it runs.
- Indexes are recreated by `setupDatabaseIndexes`, which already runs afterwards.

**Interfaces:**
- Consumes: Tasks 2, 3 and 4.
- Produces: `createBoardSession({ boardStore, recoveryStore, profileManager, getCurrentProfile, rebuildMenu, now, newId, debugLog })` returns `session`:
  - `state(): { profile, status: 'idle'|'loading'|'ready'|'failed'|'unreadable', doc|null, generation: number }`
  - `open(): Promise<{ doc, board, recovery: null|{ savedAt, handoff, boardId }, notice?, generation }>`:
    - **captures `profile = getCurrentProfile()` here.** Every later recovery write and retire uses the captured profile, never `getCurrentProfile()`, so a late write from the old page can't land in the new profile mid-switch;
    - sets status `loading`, bumps the generation and clears the fence;
    - when `boardStore.load` throws `unreadable`, sets status `unreadable` and returns `{ unreadable: true }`;
    - drops any recovery `handoff` older than **15 minutes** (`now() - savedAt`), so the record falls back to the normal crash prompt.
  - `startEmpty(): Promise<{ layout, generation }>`. Allowed only when status is `unreadable`. Calls `boardStore.resetUnreadable`.
  - `resolveRecovery(choice: 'restore'|'discard'): Promise<{ layout }>`:
    - `restore` returns the recovery layout and keeps the record;
    - `discard` retires the record and returns the saved board layout;
    - if the record's `boardId` is no longer in the document, the layout is restored onto the active board.
  - `reportReady(generation, ok: boolean): void`. A stale generation is ignored. Calls `rebuildMenu()`.
  - `saveRecovery(layout): Promise<{ skipped?: true, retired?: true }>`:
    - refused unless status is `ready` and unfenced;
    - when `layout` equals the active board's saved layout, ignoring `selected`, it **retires instead of writing**. Many `saveProfileState()` callers (navigation, keyboard manager, DOM init) fire without an edit, and an unchanged show must never trigger a crash prompt.
  - `end(reason: 'clean-exit'|'switch'|'backup-restore'|'library-import'|'profile-deleted'): Promise<void>`. Fences first, then retires (`clearAll` for `library-import`). The fence stays until the next `open()`. This is the only way out of a session. Once `rendererGone()` has run, `clean-exit` and `switch` keep the record.
  - `handoff(reason: 'update'|'renderer-crash'): Promise<void>`. Fences, then calls `recoveryStore.markHandoff(capturedProfile, reason)`.
  - `rendererGone(): void`. Calls `handoff('renderer-crash')`, and from then on `end('clean-exit')` and `end('switch')` keep the record.
- IPC channels (`IPC.BOARDS.*` → `board:*`): `OPEN`, `START_EMPTY`, `RESOLVE_RECOVERY`, `REPORT_READY`, `SAVE_RECOVERY`, `GET_STATE`. Every handler returns `{ success, data }` or `{ success:false, error }`.
- Preload: `secureElectronAPI.boards.{open, startEmpty, resolveRecovery, reportReady, saveRecovery, getState}`.
